# Data

## Source

This directory contains synthetic billing data formatted to the FOCUS specification (FinOps Open Cost and Usage Specification v1.0). No real billing data is exposed.

The dataset is generated by `generate_synthetic.py` using a fixed random seed for reproducibility. Re-running the generator produces identical output.

## Schema

The CSV uses a subset of FOCUS v1.0 required and recommended columns:

| Column | Type | Description |
|--------|------|-------------|
| BilledCost | decimal | Cost reflected on the invoice for this charge |
| BillingAccountId | string | Account that owns the billing relationship |
| BillingPeriodStart / End | ISO datetime | The billing month boundaries |
| ChargeCategory | string | Usage / Tax / Credit / etc. |
| ChargeDescription | string | Human-readable description of the line item |
| ChargePeriodStart / End | ISO datetime | The day this line item covers |
| ConsumedQuantity | decimal | Hours of compute consumed |
| ConsumedUnit | string | Unit of consumption (Hours) |
| EffectiveCost | decimal | Cost after discounts and reservations |
| ListCost | decimal | Cost at on-demand list price |
| ListUnitPrice | decimal | On-demand price per unit |
| PricingCategory | string | Standard / Reserved / Spot |
| PricingQuantity | decimal | Quantity used for pricing |
| ProviderName | string | Cloud provider (AWS) |
| RegionId / RegionName | string | Region the workload ran in |
| ResourceId | string | The specific instance or resource |
| ResourceType | string | Instance type (g5.xlarge, p4d.24xlarge, etc.) |
| ServiceCategory | string | Compute / AI and Machine Learning |
| ServiceName | string | Amazon Elastic Compute Cloud |
| Tags | JSON string | Key-value tags including cost-team |

## Engineered patterns

The synthetic data is deliberately structured to demonstrate FinOps signals an analyst would catch:

1. **Untagged research workload**: One GPU instance (`i-research-gpu-001`) is missing the `cost-team` tag. The `tag_compliance.py` script should surface this as the highest-impact remediation target.

2. **Reserved Instance under-utilization**: The training instance and CPU management instances run on Reserved pricing, but at variable utilization. RI coverage analysis should show gaps.

3. **Spot opportunity**: One Team B inference instance runs entirely on Spot. The other inference instances are on-demand. The spot opportunity for the on-demand workloads should surface in `gpu_cost_analyzer.py`.

4. **Training spike pattern**: The Team A training instance (`p4d.24xlarge`) doubles its hourly usage during week three of the dataset. This shows up as a clear time-series spike when the data is plotted.

5. **Weekend inference dropoff**: Inference workloads (production-facing) show ~60% reduction on weekends, while training and management instances stay constant. This pattern is realistic for B2B SaaS-style products.

6. **Variable research idle pattern**: The untagged research workload has a 15% chance of being mostly idle on any given day, simulating the "someone left a notebook running" pattern.

## Re-generating the data

```bash
cd data
python generate_synthetic.py
```

The script writes `ai-workload-synthetic.csv` in this directory.

## Pointing the scripts at real data

The analysis scripts in `/analysis` work with any FOCUS v1.0 compliant CSV. To run against your own data:

```bash
python analysis/parse_focus.py /path/to/your/data.csv
```

If your data is AWS CUR 2.0 format (which is FOCUS-aligned but uses different column names in some places), you may need to rename a few columns first.
